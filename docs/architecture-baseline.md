# Repository baseline before Tuka v2

Inspected 3 November 2026 at commit 4b1064b. Baseline: 191 Node tests and standalone regressions pass. Inventory covers first-party dist/server modules, tests, build scripts, deployment configs, migrations and existing reports; third-party map vendor code and binary feed assets are retained.

- Frontend: vanilla ES modules and map-first HTML/CSS; `dist/app.js` owns selected network, stop/route, origin/destination, preferences, active ride/journey, maps and request-generation guards. Tabs are views, not a framework router. Language is persisted and applied by i18n/language/boot modules.
- Transit contract: city-providers registry and runtime imported profiles; GTFS ZIP parser/normalizer, IndexedDB imports, compact Boston/Tilburg assets, schedules/calendars/time zones, realtime protobuf normalization. Existing imported-feed worker validates before persistence.
- Deterministic engine: planner.js calculates leave/arrive journeys, walking/transfer constraints and GTFS transfer rules. journey-follow.js updates live chronology, cancellations, skipped stops, transfer margins and deadline feasibility. stop-network/map-ui render verified shapes with approximate fallback.
- Existing passenger features: favorites/commutes/Home/Work, ride/get-off guidance, optional crowd reports, ticket/QR wallet, offline timetable reader, network selection and location detection. Existing three-position sheet and Change stop pointer-events fix must be preserved.
- AI gateway: server/model-provider.js selects Meta/Baseten with timeouts and bounded fallback. meta-intent extracts validated journey constraints; notice-translation handles current official Dutch notices; meta-site has protected Copilot chat, network tools and optional Boston live context. Chat does not yet have the current local journey or imported feed context.
- Backends: Cloudflare Worker variants for protected Meta site, private site, public API and Pages site; fixed transit/road/walking/news/ticket endpoints. Secrets stay server-side. Supabase reporting SQL and D1 migrations are existing optional infrastructure.
- UI: shared white/blue CSS, immersive map, floating navigation and tool disclosure, stop sheet, planner and Copilot dialog. Existing stableHTML protects expanded content during updates, but broad renderHome refreshes and dynamic source text require careful regression checks.
- Existing evidence: unit/regression tests, browser reports at 320/390/1280, public Metlink import audit and clearly labeled mocked transit/basemap screenshots. No physical Android or field-trip acceptance is implied.

V2 scope: add a bounded journey-context contract, deterministic Guardian assessment and alternative selection, optional validated AI explanations, contextual map actions and focused shared UI refinements. Reuse the existing engine, alerts and provider gateway. No merge or deployment without explicit approval. V1 Dutch closeout precedes a separate v2 feature branch.
